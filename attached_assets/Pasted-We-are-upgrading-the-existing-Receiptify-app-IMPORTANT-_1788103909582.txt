IMPORTANT:
Do NOT rebuild the whole app.
Do NOT change the existing Receiptify visual identity, colours, typography, bottom navigation, Scan tab, Analytics tab, My Receipts tab or Account tab unless required for integration.

==================================================
1. CURRENT PROBLEM
==================================================

At the moment, the Split section is too basic.

A current Split Folder only shows things like:
- folder/person name
- project name
- total
- receipt count
- members
- invite/remove member
- receipts inside the folder

There are almost no useful actions.

We want to turn Split into a proper shared expense and bill-splitting workspace.

The Split feature should support:

1. Ongoing shared expenses using Shared Folders
2. One-off bill splitting
3. Item-level assignment from scanned receipts
4. Custom amounts
5. Subfolders
6. People and permissions
7. Payment requests
8. Stripe Connect-ready payment architecture

31. STRIPE CONNECT ARCHITECTURE
==================================================

Receiptify must NOT hold user money.

Do NOT build:

Receiptify wallet
Stored balance
Internal custody
Manual payout system

Payments should eventually use:

Stripe Connect

Architecture:

Recipient connects Stripe account.

Payer pays.

Stripe processes payment.

Funds are credited to recipient’s connected Stripe account.

Stripe handles payout to recipient’s bank.

Receiptify only:

- creates payment request
- stores Stripe references
- displays status
- listens for Stripe webhook updates
- marks requests paid
- updates folder balances

Build the system as Stripe Connect-ready.

If Stripe credentials are not configured:

Create:
- database models
- payment request states
- service layer placeholders
- test/development mode

Do NOT fake live payments.
